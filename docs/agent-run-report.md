# Отчёт о запуске: adc_agent.py

Пример реального прогона агента конкурентной разведки — что он сделал и что
нашёл. Зафиксировано как референс: как выглядит корректная работа агента,
его guardrails и разделение источников (реестр vs. веб) на живых данных.

## Параметры запуска

| | |
|---|---|
| Дата запуска | 2026-08-22 |
| Модель | `claude-opus-5` |
| Запрос | «Подготовь сводку по значимым обновлениям в ADC-исследованиях за последние 30 дней, и отдельно найди свежие новости о сделках или партнёрствах по ADC в онкологии за это же время, которых нет в реестре клинических испытаний.» |
| Инструменты | `fetch_adc_trials` (реестр ClinicalTrials.gov) + `web_search_20250305` (встроенный серверный tool Claude API, `max_uses: 5`) |
| Окно данных | ≈ 23 июля — 22 августа 2026 (`days_back=30`) |

## Ход выполнения

1. Агент вызвал `web_search` с запросом `"ADC licensing deal oncology August
   2026"`, затем — реестр (`fetch_adc_trials({'days_back': 30})`), затем ещё
   два уточняющих веб-поиска: по сделкам/партнёрствам и по решениям FDA.
   Всего 3 обращения к `web_search` из лимита `max_uses: 5` и 1 к
   `fetch_adc_trials` — агент сам решил, в каком порядке и сколько раз
   обращаться к каждому источнику.
2. Оба типа инструментов отработали в одном цикле `run_agent()`: реестр — как
   обычный клиентский tool (мы выполняем `execute_tool` и возвращаем
   `tool_result`), веб-поиск — как серверный tool (Anthropic выполняет поиск
   сама, результат уже приходит внутри `response.content` как
   `server_tool_use` + `web_search_tool_result`, наш код это только
   логирует).
3. Финальная сводка строго разделяет источники по требованию системного
   промпта: каждый пункт помечен `[Реестр]` (NCT ID + ссылка) либо `[Веб]`
   (URL + дата публикации). Там, где реестр и веб дали расходящиеся данные
   (см. кейс NextCure/LigaChem ниже), агент не смешал их в одном
   утверждении, а явно пометил расхождение как требующее проверки.

## Известная проблема, вскрытая этим прогоном

Первая попытка подключить веб-поиск использовала более новый вариант
`web_search_20260209` (актуальный для `claude-opus-5`, с динамической
фильтрацией). Он тянет за собой встроенный `code_execution`-сэндбокс, и
модель попыталась вызывать через него ещё и наш кастомный
`fetch_adc_trials` — без передачи `container_id` между запросами ручной
цикл `run_agent()` этого не поддерживает. Запрос упал с `400: container_id
is required when there are pending tool uses generated by code execution
with tools`. Исправлено откатом на базовый `web_search_20250305` — он не
тащит за собой отдельную песочницу и не конфликтует с кастомным tool'ом в
ручном agentic-цикле. Сводка ниже — результат прогона уже с этим фиксом.

## Наблюдение по формату

В сыром выводе модель один раз вставила служебную фразу («Реестр отработал.
Уточню веб-часть ещё двумя запросами...») прямо перед заголовком финальной
сводки, без разделителя — артефакт склейки текстовых блоков из разных ходов
цикла (`"".join(block.text ...)` в `run_agent()` не добавляет между ними
перенос строки). На результат не повлияло, но при желании сделать вывод
чище можно фильтровать текст только последнего хода, а не всех подряд.

## ⚠️ Ограничения данных (прочитать до выводов)

1. **Инструмент `fetch_adc_trials` возвращает только текущий статус и дату последнего обновления записи, но не показывает, *что именно* изменилось.** Поэтому ниже я указываю «запись обновлена + текущий статус», а не «статус сменился» — утверждать факт смены статуса по этим данным нельзя. Это «недостаточно данных» для всех пунктов типа «смена фазы/статуса».
2. В выдаче реестра присутствует **посторонний шум** — исследования без ADC (МРТ-визуализация простаты, лёгких, почек; NCT05424783, NCT07768046, NCT07743749, NCT07231627). Их я исключил.
3. Две записи **без указания фазы** (NCT07767799, NCT07736001) — помечены как недостаточно данных.
4. Веб-поиск по сделкам за последние 30 дней дал **мало релевантного**: большинство найденных сделок (Gilead/Tubulis, GSK/Nuvalent, Lilly/CrossBridge, Day One/Mersana, Roche/C4) датированы **до** окна. Внутри окна подтверждено немного — см. раздел 2.
